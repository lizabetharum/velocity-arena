Prueba de Turning

Aprende cómo este programa MakeCode conduce tu robot a través de patrones de arco, prueba cómo la estadística TURNING da forma al movimiento y vigila el borde mientras trabaja.

Abrir en MakeCode
Resumen

¿Qué hace este programa?

Este programa prueba cómo tu robot se mueve en arcos según tu estadística TURNING. Mientras conduce, vigila continuamente los sensores de la pista y se recupera si toca el borde. Puedes cambiar el estilo de arco a mitad de sesión y simular diferentes momentos de un partido para ver cómo ENDURANCE afecta la velocidad.

La idea clave: tu estadística TURNING no solo controla si giras — controla la forma del patrón que tu robot traza alrededor del ring. Probarlo aquí te dice qué esperar en un partido real.

⚠️
Antes de ejecutar: Configura SPEED y ENDURANCE en el bloque on start con las estadísticas reales de tu personaje. Ambos empiezan en cero — déjalos ahí y el robot no se moverá.
🔄
Los roles de los botones cambiaron respecto a la Prueba de Endurance. El Botón B ahora cicla el valor de TURNING. El Botón A+B ahora cicla el tiempo simulado del partido. No hay un botón de parada de emergencia dedicado en este programa — presiona A de nuevo para dejar que el tiempo de prueba expire, o apaga el micro:bit.
Controles

Tres botones. Roles diferentes a los anteriores.

A

Ejecutar la Prueba

Calcula la potencia y la configuración de arco a partir de tus estadísticas, luego conduce el patrón de arco completo durante TEST_DURATION_MS. Observa la forma que traza y cómo reacciona en el borde.

B

Ciclar Valor de TURNING

Cambia entre 2 → 5 → 10 → 2. Cada valor cambia el conteo de segmentos de arco y la nitidez. Configura esto antes de presionar A para probar un patrón diferente.

A+B

Ciclar Tiempo de Partido

Cicla entre 0 → 60 → 120 → 180 segundos. Muestra el tiempo como texto en la pantalla LED. Úsalo para simular cómo el decaimiento de endurance afecta el arco en diferentes momentos del partido.

Bloque por Bloque

¿Cómo funciona cada sección?

on start — Configuración de Variables
Cargando bloques desde MakeCode…
let TURNING = 2
let TEST_DURATION_MS = 15000
let BORDER_CHECK_MS = 60
let BORDER_PIVOT_MS = 400
let BORDER_PIVOT_POWER = 50
let BACKUP_MS = 600
let BASE_SEGMENT_MS = 1800
let BORDER_THRESHOLD = 200
let SPEED = 0
let ENDURANCE = 0

Se ejecuta una vez cuando el micro:bit se enciende. Llena todos los valores iniciales antes de que se presione cualquier botón.

1
TURNING = 2 — Comienza con el patrón suave de 2 arcos. Cámbialo con el Botón B antes de ejecutar.
2
TEST_DURATION_MS = 15000 — Cada prueba dura 15 segundos (15‬000ms). Aumenta esto para más tiempo de observación.
3
BASE_SEGMENT_MS = 1800 — Nuevo en este programa. Controla la "longitud base" de cada segmento de arco antes de dividirse entre TURNING. 1800ms × 12 = 21.6 segundos de tiempo total de arco por ciclo.
4
SPEED = 0 y ENDURANCE = 0 — Llénalos con las estadísticas reales de tu personaje antes de subir.
on button A pressed — Ejecutar la Prueba de Arco
Cargando bloques desde MakeCode…
input.onButtonPressed(Button.A, function () {
    computeStats()
    basic.showString("" + (TURNING))
    running = true
    testStart = input.runningTime()
    while (running && input.runningTime() - testStart < TEST_DURATION_MS) {
        lastTurnWasLeft = !(lastTurnWasLeft)
        for (let index = 0; index < TURNING; index++) {
            if (input.runningTime() - testStart >= TEST_DURATION_MS) {
                running = false
                break
            }
            if (TURNING == 1) {
                CutebotPro.pwmCruiseControl(currentPower, currentPower)
            } else if (lastTurnWasLeft) {
                CutebotPro.pwmCruiseControl(Math.round(currentPower * (1 - turnRatio)), currentPower)
            } else {
                CutebotPro.pwmCruiseControl(currentPower, Math.round(currentPower * (1 - turnRatio)))
            }
            driveAndWatch(thisDuration)
            if (watchResult == 1) {
                handleBorder()
                break
            }
            basic.pause(80)
        }
    }
    running = false
    basic.showLeds(`
        # . . . #
        . # . # .
        . . # . .
        . # . # .
        # . . . #
        `)
    basic.pause(500)
    basic.clearScreen()
})

El bucle principal de la prueba. Este es el bloque más complejo del programa — tiene un bucle dentro de un bucle. Así se lee:

1
llamar a computeStats → calcula currentPower, turnRatio y thisDuration a partir de tus estadísticas. Luego muestra el valor actual de TURNING en pantalla.
2
bucle while exterior — sigue ejecutándose hasta que el tiempo expire. Cada iteración: cambia de dirección (lastTurnWasLeft), luego ejecuta un conjunto completo de segmentos TURNING.
3
bucle for interior — se ejecuta TURNING veces. Cada paso verifica si el tiempo se agotó, ajusta las velocidades de las ruedas según la dirección actual, llama a driveAndWatch, luego pausa 80ms entre segmentos.
4
Lógica de velocidad de ruedas: Si lastTurnWasLeft es verdadero → rueda izquierda más lenta, rueda derecha más rápida (arco a la izquierda). Si es falso → izquierda más rápida, derecha más lenta (arco a la derecha). La diferencia la controla turnRatio.
5
Si driveAndWatch establece watchResult = 1 (borde alcanzado), llama a handleBorder y sal del bucle interior para reiniciar el bucle exterior desde una dirección nueva.
6
Cuando el tiempo expire: detiene todos los motores, muestra una ✕ en la pantalla LED, luego la borra.

input.onButtonPressed(Button.AB, function () {
    if (simulatedMatchTime == 0) {
        simulatedMatchTime = 60
        basic.showString("60s")
    } else if (simulatedMatchTime == 60) {
        simulatedMatchTime = 120
        basic.showString("120s")
    } else if (simulatedMatchTime == 120) {
        simulatedMatchTime = 180
        basic.showString("180s")
    } else {
        simulatedMatchTime = 0
        basic.showString("0s")
    }
    basic.pause(500)
    basic.clearScreen()
})

Cicla el tiempo simulado del partido: 0 → 60 → 120 → 180 → 0. El tiempo actual se muestra como texto en la pantalla LED (ej. "60s"). Esto alimenta a computeStats para aplicar el decaimiento de endurance — así puedes sentir cómo un robot cansado traza arcos de forma diferente al final de un partido.

⚡
Esto no es una parada de emergencia. Si necesitas detener el robot urgentemente, deja que el tiempo de prueba expire o apaga el micro:bit. No hay botón de parada de emergencia en este programa.
function computeStats — Calcular Potencia y Forma del Arco
Cargando bloques desde MakeCode…
function computeStats () {
    currentPower = SPEED * 100 / 20
    totalArcTime = BASE_SEGMENT_MS * 12
    thisDuration = Math.round(totalArcTime / TURNING)
    turnRatio = 0.2 + TURNING * 0.02
    turnRatio = Math.min(turnRatio, 0.4)
    DECAY_RATE = 20 - ENDURANCE
    endurancePercent = 100 - DECAY_RATE * simulatedMatchTime / 40
    endurancePercent = Math.max(endurancePercent, 20)
    enduranceFactor = endurancePercent / 100
    currentPower = Math.round(currentPower * enduranceFactor)
    currentPower = Math.max(currentPower, 15)
}

Esta función calcula todo antes de que cualquier motor gire. Hace dos trabajos: establece la forma del arco (turnRatio y thisDuration) y aplica el decaimiento de endurance a currentPower.

currentPower = SPEED × 100 ÷ 20 ← convierte estadística a % de motor
totalArcTime = BASE_SEGMENT_MS × 12 ← 1800 × 12 = 21.600ms total
thisDuration = totalArcTime ÷ TURNING ← tiempo por segmento
turnRatio = 0.2 + TURNING × 0.02 ← nitidez del arco (máx 0.40)
currentPower × enduranceFactor ← decaimiento aplicado al final
📐
Ejemplo de thisDuration: Con TURNING = 5 → 21600 ÷ 5 = 4320ms por segmento. Con TURNING = 10 → 21600 ÷ 10 = 2160ms por segmento. Más segmentos = más corto cada uno.
〰️
Ejemplo de turnRatio: TURNING = 2 → ratio = 0.24 (arco suave). TURNING = 10 → ratio = 0.40 (limitado, el más cerrado posible). El límite evita que las ruedas giren hacia atrás.
⬇️
Decaimiento de Endurance: La misma matemática que la Prueba de Endurance — la potencia disminuye según la estadística ENDURANCE y simulatedMatchTime. Un robot con ENDURANCE bajo trazará arcos más lentamente a 180s que a 0s.
function driveAndWatch — Conducir + Monitorear Sensores Simultáneamente
Cargando bloques desde MakeCode…
function driveAndWatch (ms: number) {
    watchResult = 0
    elapsed = 0
    while (elapsed < ms) {
        halfChunk = Math.min(BORDER_CHECK_MS, ms - elapsed)
        basic.pause(halfChunk)
        elapsed += halfChunk
        borderSide = checkBorder()
        if (borderSide > 0) {
            CutebotPro.stopImmediately(CutebotProMotors.ALL)
            watchResult = 1
            return
        }
        if (elapsed >= ms) {
            return
        }
        remainChunk = Math.min(BORDER_CHECK_MS, ms - elapsed)
        basic.pause(remainChunk)
        elapsed += remainChunk
        borderSide = checkBorder()
        if (borderSide > 0) {
            CutebotPro.stopImmediately(CutebotProMotors.ALL)
            watchResult = 1
            return
        }
    }
}

Esta es una nueva función que no está en la Prueba de Endurance. En vez de conducir un segmento completo y luego revisar los sensores, esta función los revisa durante la conducción — hasta dos veces por ventana de 60ms. Eso significa que el robot puede reaccionar al borde en medio de un segmento en lugar de esperar hasta que termine.

1
Establece watchResult = 0 (sin borde) y elapsed = 0 (tiempo usado hasta ahora). Los motores ya están en marcha — el código llamador configuró las velocidades de las ruedas antes de llamar a esta función.
2
bucle while — sigue hasta que elapsed ≥ ms. Cada paso: espera un pequeño fragmento de tiempo, agrégalo a elapsed, revisa sensores. Dos verificaciones de sensores por iteración para reacción más rápida.
3
halfChunk = Math.min(BORDER_CHECK_MS, ms − elapsed) — esto evita superar el tiempo objetivo. Si quedan menos de 60ms, espera solo el resto, no un 60ms completo.
4
Si checkBorder() devuelve algo distinto de 0 → establece watchResult = 1 y retorna de inmediato. El código llamador (bucle Botón A) ve watchResult = 1 y llama a handleBorder.
💡
¿Por qué no pausar el segmento completo? Si el robot condujera 4.320ms sin revisar sensores, podría penetrar profundamente en el borde blanco antes de reaccionar. Esta función verifica cada 60ms, por lo que a velocidad máxima se detiene dentro de 1–2 ciclos de sensor al tocar el borde.
function checkBorder — Leyendo los Sensores
Cargando bloques desde MakeCode…
function checkBorder () {
    if (sensor1State > BORDER_THRESHOLD) {
        return 1
    } else if (sensor4State > BORDER_THRESHOLD) {
        return 2
    } else if (sensor2State > BORDER_THRESHOLD || sensor3State > BORDER_THRESHOLD) {
        return 3
    }
    return 0
}

Igual que la Prueba de Endurance — lee cuatro sensores y devuelve un número según qué lado (si alguno) detectó el borde blanco.

function handleBorder — Recuperarse del Borde
Cargando bloques desde MakeCode…
function handleBorder () {
    CutebotPro.stopImmediately(CutebotProMotors.ALL)
    basic.pause(50)
    CutebotPro.pwmCruiseControl(-1 * BORDER_PIVOT_POWER, -1 * BORDER_PIVOT_POWER)
    basic.pause(BACKUP_MS)
    CutebotPro.stopImmediately(CutebotProMotors.ALL)
    basic.pause(100)
    if (borderSide == 1) {
        CutebotPro.pwmCruiseControl(BORDER_PIVOT_POWER, -1 * BORDER_PIVOT_POWER)
        basic.pause(BORDER_PIVOT_MS + Math.randomRange(-80, 80))
        lastTurnWasLeft = false
    } else if (borderSide == 2) {
        CutebotPro.pwmCruiseControl(-1 * BORDER_PIVOT_POWER, BORDER_PIVOT_POWER)
        basic.pause(BORDER_PIVOT_MS + Math.randomRange(-80, 80))
        lastTurnWasLeft = true
    } else {
        CutebotPro.pwmCruiseControl(-1 * BORDER_PIVOT_POWER, -1 * BORDER_PIVOT_POWER)
        basic.pause(BACKUP_MS + 300)
        CutebotPro.stopImmediately(CutebotProMotors.ALL)
        basic.pause(100)
        CutebotPro.pwmCruiseControl(BORDER_PIVOT_POWER, -1 * BORDER_PIVOT_POWER)
        basic.pause(BORDER_PIVOT_MS * 2)
        lastTurnWasLeft = false
    }
    CutebotPro.stopImmediately(CutebotProMotors.ALL)
    basic.pause(100)
    recheck = checkBorder()
    if (recheck > 0) {
        borderSide = recheck
        CutebotPro.pwmCruiseControl(-1 * BORDER_PIVOT_POWER, -1 * BORDER_PIVOT_POWER)
        basic.pause(BACKUP_MS)
        CutebotPro.stopImmediately(CutebotProMotors.ALL)
        basic.pause(100)
        CutebotPro.pwmCruiseControl(-1 * BORDER_PIVOT_POWER, BORDER_PIVOT_POWER)
        basic.pause(BORDER_PIVOT_MS)
        CutebotPro.stopImmediately(CutebotProMotors.ALL)
        basic.pause(100)
    }
}

La misma secuencia de recuperación que la Prueba de Endurance — detener, retroceder, girar según qué lado tocó el borde. Una nueva adición en esta versión: lastTurnWasLeft se establece según la dirección de recuperación, así el patrón de arco se reanuda con la orientación correcta después de un evento de borde.

1
Detener y retroceder durante BACKUP_MS (600ms) para alejarse de la zona del borde.
2
Girar y alejarse según borderSide. Peligro a la izquierda → girar a la derecha. Peligro a la derecha → girar a la izquierda. Directo → retroceso extra + giro mayor.
3
Restablecer dirección de arco: Después de recuperarse hacia la izquierda (girando a la derecha), establece lastTurnWasLeft = false para que el siguiente segmento arcé a la derecha — alejado del lado que se acaba de tocar.
4
Reverificar — si aún está en blanco, hace un retroceso y giro más antes de reanudar el bucle principal.
Variables

¿Qué significa cada variable?

Dorado = tú lo configuras. Cian = calculado automáticamente. Púrpura = constante fija. Verde = nuevo en este programa.

SPEED Tú configuras
Estadística de velocidad de tu personajeEstablece la potencia base del motor. Se usa para calcular currentPower antes de aplicar el decaimiento.
ENDURANCE Tú configuras
Estadística de resistencia de tu personajeControla cuánto disminuye la potencia del motor durante el tiempo simulado del partido. ENDURANCE bajo = ralentización notable a 180s.
TURNING Tú configuras (con B)
Número de segmentos de arco por ciclo de conducciónSe configura presionando el Botón B. Opciones: 2, 5 o 10. Controla tanto el conteo de segmentos como la nitidez del arco (mediante turnRatio).
turnRatio Nuevo
Diferencia de velocidad de ruedas que crea el arcoCalculado como 0.2 + TURNING × 0.02, limitado en 0.40. Cuanto más alto, más cerrado es el arco.
thisDuration Nuevo
Cuánto dura cada segmento de arco individual (ms)Calculado como totalArcTime ÷ TURNING. Más segmentos = más corto cada uno.
totalArcTime Nuevo
Presupuesto total de tiempo para un ciclo completo de arco (ms)Siempre BASE_SEGMENT_MS × 12 = 21.600ms. Dividido entre todos los segmentos para obtener thisDuration.
lastTurnWasLeft Nuevo
Registra en qué dirección fue el último arcoCambia en cada iteración del bucle exterior para que los arcos alternén izquierda/derecha. También lo restablece handleBorder para continuar en la dirección correcta después de la recuperación.
watchResult Nuevo
Salida de driveAndWatch0 = segmento completado limpiamente. 1 = borde alcanzado a mitad del segmento. El bucle principal verifica esto después de cada llamada a driveAndWatch.
currentPower Auto
Potencia real del motor enviada a las ruedas (0–100)Calculado a partir de SPEED, luego reducido por el decaimiento de endurance. El mínimo es 15 en este programa (ligeramente diferente del piso del 20% de la Prueba de Endurance).
simulatedMatchTime Auto
Tiempo "simulado en el partido" para pruebas de enduranceSe configura presionando A+B. 0 = inicio, 180 = cerca del final. Se pasa a computeStats para aplicar decaimiento.
BASE_SEGMENT_MS Constante
Longitud base del segmento de arco antes de dividir entre TURNINGConfigurado en 1800ms. Cámbialo para hacer todos los segmentos más largos o cortos sin tocar TURNING.
BORDER_THRESHOLD Constante
Umbral de brillo del sensor para detección del bordeConfigurado en 200. Lecturas del sensor por encima de esto = borde blanco detectado.
Siguientes Pasos

Consejos para usar este programa

01

Configura las estadísticas antes de subir

Encuentra SPEED = 0 y ENDURANCE = 0 en el bloque on start. Reemplaza los ceros con los valores reales de tu personaje o nada se moverá.

02

Prueba los tres valores de TURNING

Ejecuta con TURNING = 2, 5 y 10 en secuencia. Observa el patrón en el suelo que traza cada uno. La diferencia es especialmente visible con estadísticas de SPEED altas.

03

Combina TURNING + tiempo de partido

Configura el tiempo del partido a 180s con A+B, luego ejecuta tu valor de TURNING elegido. Compáralo con 0s. Si los arcos son notablemente más cerrados o lentos, ENDURANCE está afectando tu estilo de arco.

04

Observa la recuperación del borde

Usa un TEST_DURATION_MS más largo (ej. 20000 = 20s) para darle al robot más tiempo de tocar el borde y recuperarse. Observa cómo handleBorder ajusta la dirección del arco después de cada incidente.

05

Ajusta BASE_SEGMENT_MS

Bajar BASE_SEGMENT_MS hace todos los segmentos más cortos. Subirlo los hace más largos. Prueba 900 para arcos de media longitud o 3600 para el doble — observa cómo cambia la cobertura sin tocar TURNING.

06

Sin parada de emergencia — planifica con anticipación

A+B no es un botón de parada aquí. Coloca el robot en un área segura antes de probar, manténte cerca del interruptor de encendido, y usa un TEST_DURATION_MS más corto si te preocupa el comportamiento descontrolado.
