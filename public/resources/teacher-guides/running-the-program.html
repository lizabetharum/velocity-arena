RUNNING THE PROGRAM

Running the program — 16 days, decision by decision.

What facilitators actually do across the four weeks — not what's in the code, not the data plumbing, not the deploy pipeline. The operational playbook: when to intervene, when to hold back, what to collect, what to never share with students, and where the failure modes hide. Read this before Week 1; come back to it whenever you're about to do something risky.

01 The mental model — what this program actually is.

If you only remember one thing from this page: the bots are a vehicle for the math, not the other way around. Students who leave with a working bot but no math means the program failed.

  • It's a math program in a robotics costume. Proportional reasoning, slope, distance, quadratic, percent change, residuals, systems of inequalities. The 16-day arc walks students from "formulas are recipes" to "formulas are predictions I revise from data."
  • One driving question stays on the wall for 16 days: "How can you use data, equations, and code to build a robot athlete that wins on math, not luck?"
  • The four Program Goals — Transfer · Ownership · Failure · Teach — are evidence statements, not slogans. Goal 4 (a stranger completes 3 mini-challenges after a single student explanation) is the summative on Day 16. See the Toolkit Guide.
  • The math destination lives in the Math Pre-Brief — read it once before Week 1. Five mathematical relationships, four understandings to leave with.
02 Before Day 1 — pre-season prep. ~3 hours, once

You can't run this program from cold. Three hours of preparation in the days before Week 1 saves the program from the most common failure modes.

  • Read the four walkthroughs in order: Math Pre-Brief → Progression in Context → Evidence in Context → Resources in Context. The order matters — destination, journey, what to look for, what to reach for.
  • Memorize the Loss Recovery Protocol word-for-word. You'll use it from Day 7 on. The script only works if you can say it calmly under pressure without improvising.
  • Calculate all four stat formulas for every point value 1–8 by hand, in under 10 seconds each. Motor% = Speed × 5 · Charge% = Power² · decay rate = (20−E) × 1.5 · turn ratio = 0.2 + T × 0.02. If you hesitate when a student asks mid-match, you become unreliable at the moment that matters most.
  • Lay out the room. Reserve wall space for: Driving Question · Commissioner's Rules · Bot Names · Leaderboard · Rivalry Cards. Tape the field down with measuring tape.
  • Confirm your site's data infrastructure works — open the Spreadsheets Reference and check that you can see your per-site sheets. If you can't, escalate now, not on Day 1.
03 The daily rhythm — every day, in this order. 6 blocks · ~3.5 hrs

The math changes day to day. The structure of the day does not. The predictability is the point — it lowers cognitive load so students spend it on the math, not on figuring out what's next.

#BlockMinWhat it is
01 Hook 25 Physical or kinesthetic. No formula yet. Primes the concept.
02 Challenge Block 55 Core math instruction. Formula derivation. Error analysis.
03 Snack 20 Off-schedule. Don't talk about math.
04 Match · Build · Make 90 Program and test, OR Predict → 3 matches → Loss Recovery. The competitive heart.
05 Open Lab 30 Two self-selected tracks. Student-directed time.
06 ENDS 10 One reflection prompt. Every student. Every day.
04 Match days — three non-negotiables. D 06 → D 15

Match days are when the modeling cycle becomes visible. These three rules are how a match stops being drama and starts being data. Hold them like they're load-bearing — because they are.

01

No bot moves until every team has a written, formula-cited prediction.

The rule that turns a match from drama into data. Predict before the bots leave the box. If a team can't state their formula + input + predicted output, they're not ready to run.

02

Residual after every match.

Predicted − actual = a signed number. When the gap is > 20%, the team writes a one-sentence cause naming a specific model parameter. The residual is the math operation that makes Goal 3 (productive failure) real.

03

Loss Recovery for every losing team. Every time.

Not just the visibly upset ones. Especially the team that's "fine." Name feeling → 30s silence → dashboard one stat → write the next change in pen. The team doesn't code for the next match until the plan is on paper.

05 Three rules students must know — by name.

These aren't optional context. Make sure every student can state them by the end of Week 1. The first is the math; the other two are how the game actually works.

  • The Budget equation: S + E + T + P = 20. The = means balance, not arithmetic. Every point given to one stat is a point taken from another. This frame drives every allocation for four weeks.
  • Own goals count. A ball crossing either goal line scores for that net's attacker. (Surface this on Day 6 before Match Day 1 — otherwise the first own-goal is a long argument instead of a learning moment.) See the Match Rules page.
  • Robot Off the Field: facilitator places the bot at the nearest edge, at the center line, facing inward. Referee presses Button B to try to reset the match loop.

07 Site-specific knowledge. Know once, use daily

Every pilot site has a code that drives data routing. You don't edit URLs or sheets — but you do need to know what's connected to what, and where your data lives.

  • Your site code: NY1 = Gotham Tech · NY2 = Claremont · NY3 = South Bronx Community Charter · TN = Tennessee. The code shows up in dashboard URLs as cohortTag=NY1 etc. If a URL is missing the tag, the data won't route.
  • Five spreadsheets to know exist (all linked from the Spreadsheets Reference — gated):
    • • Loadouts — shared across all sites. Where stat-card lesson submissions land.
    • • Dashboard (per-site) — where match data lands.
    • • Pre-Task Diagnostic (per-state) — Day 1 baseline.
    • • Post-Task Diagnostic (per-state) — Day 15 growth measure.
    • • What-If Analysis — shared across all sites.
  • If data isn't landing, it's not your problem to fix. Note what's missing, when, and from whom — and escalate. Don't try to edit a sheet ID, redeploy anything, or change a URL.

09 When not to intervene.

The hardest part of running this program is what you don't say. These are four moments where over-helping breaks the learning.

Days 1–5 stat lessons Don't say "invest more in Power" or "Speed matters most." Observe and record only. Let the Season 1 match data answer "does it matter to the score?" — that's the whole point of the modeling cycle. If you reveal the answer, students never get to discover the relationship between stat and outcome.
Open Lab — any day One question per stop ("What are you trying?"), then 10 seconds of silence, then move on. Don't suggest tasks. Don't supervise. Student-directed time only works if you stay out of the direction.
Commissioner's Meeting · Day 12 Hold the math standard. "Can anyone verify?" is your move. Dismiss "I don't like it" arguments that don't cite a number and a calculation. Don't argue the politics — only hold the line that every claim needs a number.
Day 16 Exhibition Redirect visitor confusion back to the student. If the student struggles to explain, ask a simpler question to the student — not the visitor. Don't answer for them. The Goal 4 summative depends on a student doing the teaching, not you saving the moment.
10 Critical "don't do this."

Each of these has burned a program before. They're worth memorizing — not just reading.

Don't · Day 1–5 Don't tell students which stat to invest in. Hold judgment. The Season 1 match data is the answer to "does it matter?" — your job in Week 1 is to make sure that answer is discoverable.
Don't · sharing Don't share the Worksheets & Answer Keys Drive folder URL raw. The folder is anyone-with-link viewable; route teachers through the /teachers.html password gate.
Don't · sharing Don't share the /teachers.html URL with students. The student-facing site lives at the same URL minus /teachers. Use the right one.
Don't · Day 15 → 16 Don't run the Day-15 post-diagnostic on Day 16. Exhibition energy tanks participation — and you lose the post-task baseline for measuring growth. The post-diagnostic must run on Day 15.
Don't · match days Don't skip Loss Recovery for a team because they seem "fine." Especially that team. The discipline of the protocol is what makes losing into data instead of failure — and the team that looks fine is often the one quietly disengaging.
11 Things that change cohort-to-cohort. Re-check each cohort

Read these every time you prep. They're the kind of thing that's correct in this cohort but might be stale by the next one — and the kind of thing that's hardest to catch by re-reading the curriculum.

  • Follow-Through formula changed 2026-05-30 from P × 80 to 120 + (Power × 35). The new ms values run from 155 (P=1) to 540 (P=12). The lesson pages were updated to match — if you find any doc that still says Power × 80, it's stale and worth flagging.
  • Underdog Mechanic (Day 11): the last-place team gets 2 bonus stat points, so their four stats sum to 22, not 20. Announce publicly; check the math.
  • The cohortTag in dashboard URLs determines which site's sheet receives data. If a teacher emails you a dashboard URL missing the tag, data won't route — check this before Day 6.
  • Power² sweet spot is currently unconfirmed — the old "P9 overshoot" rule was tied to the previous Power × 80 formula. Frame it as a Season 1 question students can investigate, not a known answer.
12 When to escalate to the developer.

These are the moments where you stop trying and ping the developer. They're all infrastructure problems, not pedagogy problems — different toolset, different person.

  • A submission says "Sent" but no row appears in the expected sheet.
  • The diagnostic dashboard shows empty data after the post-task, even though students submitted.
  • Apps Script returns an error in the browser console when a student submits.
  • A page that worked yesterday is now 404.
  • You want to add a new pilot site (e.g., NY4) — requires code changes in the API + new env vars + new sheet setup.
  • You think a formula is wrong on a student-facing page (like the Follow-Through bug that landed wrong values in the Loadouts sheet for months).
You should never need to Open Vercel · edit config.js · redeploy anything · change a sheet ID · touch an Apps Script · run git push. If someone is asking you to, push back — those are developer tasks, not facilitator tasks. Your job is the room, the math, and the kids.
