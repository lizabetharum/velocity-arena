How to Run Skills Arena

Everything students need to get their bot driving on the mat: load the code, enter their stats, calibrate the drive, and run Challenge 1. Watch the video first, then follow the steps.

Part 1 Set up MakeCode — once per team, per project

  1. Set up the fieldVelocity Arena mat on a flat, hard surface. You need the Cutebot Pro, a micro:bit, the squeaky ball, and the rubber ball.
  2. Open MakeCode, make a new projectGo to makecode.microbit.org → New Project → name it SkillsArena.
  3. Add the Cutebot Pro extensionClick Extensions in the toolbox (or gear ⚙ → Extensions), search cutebot, click the Cutebot Pro card. Only needed once per project — the code will not work without it.
  4. Switch to JavaScriptClick the JavaScript slider at the top (next to "Blocks"). This is text mode — the students type code, not blocks.
  5. Delete the default codeClick in the editor, press Ctrl+A (Mac: ⌘A), then Delete.
  6. Paste the starter codeOn the Skills Arena lesson page, click Copy Template, then paste into MakeCode with Ctrl+V (Mac: ⌘V). All four stats will read 0 — that's expected.

Part 2 The two places students edit

  1. Enter team stats — lines 55–58Find STUDENT ZONE A near the top. Replace each 0:
    let SPEED = ? · let POWER = ? · let ENDURANCE = ? · let TURNING = ?
    Rules: every stat at least 1, POWER ≤ 10, and the four must add to exactly 20.
  2. Find deadStraight() — the Challenge 1 functionScroll down to Challenge 1 — DEAD STRAIGHT (around line 207). The body is empty except a hint. This is where students write their driving code.
  3. Type drive(1) inside itReplace // YOUR CODE HERE with drive(1). This is the calibration run — one square, to check the bot's start-up.
  4. Download to the micro:bitClick Download and follow the prompts to copy the file onto the micro:bit. The LEDs scroll the motor/charge power, then show 1 — ready.
  5. Test it: press APut the bot on the mat at the start square. Press A. It should drive exactly one grid square and stop.
Re-flash after every change. Editing the code does nothing until they press Download again. Changed stats especially — they only take effect after a fresh flash. This is the #1 thing that confuses students.

Part 3 Calibrate, then solve Challenge 1

Important: drive(1) is not the answer to Challenge 1 — it's the calibration step. Challenge 1 starts at (1, 0) and the target is (7, 0), so the real answer is drive(6). Calibrate first, then solve.
  1. Tune the start-up with drive(1)Run it and watch. Stops short of one square → increase startupMs (line 89) by +20. Overshoots → −20. Re-download and re-test until one square is clean. Expect a value around 80–140.
  2. Tune the distance with drive(6)Change the call to drive(6). Short → increase unitMs (line 88) by +20. Overshoots → −20. Expect around 590–620.
  3. Check it holdsTry drive(4) and drive(2). If the tuning is right they land without any further adjustment. Then set it back to drive(6) — Challenge 1 solved.
  4. Move onPress B to step to Challenge 2 and keep going. The same tuned values carry through every challenge.

Buttons What the micro:bit buttons do

ButtonWhat it does
BCycles the challenge number 1 → 2 → 3 … → 10 → 1. The number shows on the LEDs so you know which one is selected.
ARuns the selected challenge. An arrow flashes, the bot moves, then a ✓ appears when it finishes.
A + BEmergency stop — kills the motors instantly, at any time. Teach this before the first run.
Teach A + B first. Before any bot touches the mat, have every student press A + B once so they know how to stop a runaway bot. It works at any moment, mid-run.

If stuck Quick fixes

SymptomFix
Code won't compile / CutebotPro is underlined redThe Cutebot Pro extension isn't added. Gear ⚙ → Extensions → search cutebot → add it.
Bot does nothing when A is pressedThe challenge function is still empty, or they didn't re-download after editing. Check deadStraight() has a drive() call, then Download again.
Changed the stats but nothing changedThey didn't re-flash. Press Download again.
LEDs never show a numberThe flash didn't complete. Re-copy the file to the micro:bit.
Stats rejected / bot behaves oddlyThe four stats must total exactly 20, each at least 1, POWER no higher than 10.
