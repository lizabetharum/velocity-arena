Launch Sequences.

A launch sequence runs once at the start of a match, before the match loop takes over. It moves the bot from its corner to the centre of the field so it can begin hunting the ball. The reference sequence below starts in the bot's home corner, drives diagonally toward the centre line, turns to face up the field, and drives straight to the ball — then hands off to lookForBall().

The four steps 04 STEPS
Step 01
Turn left from the corner
Pivot 45° in place to point the bot diagonally toward the centre line. Brief pause to settle the wheels before driving.
Step 02
Drive diagonally toward the centre line
Cruise at the team's Power setting for ~2.2 s, scaled by powerScale. Higher Power → shorter time, same distance.
Step 03
Turn right to face up the centre
Pivot 45° back the other way so the bot is now pointing up the field toward the ball zone.
Step 04
Drive straight to the ball
Final ~1.2 s cruise (Power-scaled) to reach the ball zone. Border detection re-enables and lookForBall() takes over.
Why powerScale? The pause durations are tuned for a reference motor speed of 30. When a team's allocation produces a different motorPower, the bot would travel farther or shorter than intended. Computing 30 / Math.max(1, motorPower) scales each pause inversely — faster motor → shorter pause, same distance. The Math.max(1, …) guards against divide-by-zero when a stat translates to a zero motor value.
The MakeCode REFERENCE

Paste this into a MakeCode JavaScript project alongside the match-loop globals (launchActive, motorPower, currentPower, resetRequested, ballDetected, matchRunning) and the helpers (checkBorder, handleBorder, lookForBall). Call launchSequence() once when the match starts.

launchSequence.ts JavaScript / MakeCode 
function launchSequence() {
    launchActive = true
    let powerScale = 30 / Math.max(1, motorPower)
    // ── Step 1: Turn LEFT from corner ────────────────────────
    CutebotPro.trolleySteering(CutebotProTurn.LeftInPlace, 45)
    basic.pause(300)
    CutebotPro.stopImmediately(CutebotProMotors.ALL)
    basic.pause(150)

    // ── Step 2: Drive diagonally toward centre line ───────────
    CutebotPro.pwmCruiseControl(currentPower, currentPower)
    basic.pause(Math.round(2200 * powerScale))
    CutebotPro.stopImmediately(CutebotProMotors.ALL)
    basic.pause(150)

    // ── Step 3: Turn RIGHT to face up the centre ─────────────
    CutebotPro.trolleySteering(CutebotProTurn.RightInPlace, 45)
    basic.pause(300)
    CutebotPro.stopImmediately(CutebotProMotors.ALL)
    basic.pause(150)

    // ── Step 4: Drive straight to the ball ───────────────────
    CutebotPro.pwmCruiseControl(currentPower, currentPower)
    basic.pause(Math.round(1200 * powerScale))
    CutebotPro.stopImmediately(CutebotProMotors.ALL)
    basic.pause(200)

    // ── Re-enable border detection ────────────────────────────
    resetRequested = false
    launchActive = false
    basic.pause(30)
    if (checkBorder() > 0) { handleBorder() }
    basic.pause(200)

    // ── lookForBall at mid-field ──────────────────────────────
    if (!ballDetected && matchRunning) {
        lookForBall()
    }
}
Tuning notes FOR FACILITATORS

When teams change their stat allocation, the launch sequence should still land the bot in roughly the same spot. If it doesn't, one of these is usually the cause:

  • Turn angle drift. The 45° pivots are tuned for a specific Turning value. Very low Turning may under-rotate; very high Turning may over-rotate. Tune the 45 on the trolleySteering calls per team if needed.
  • Pause times. The 2200 and 1200 ms values are calibrated for the reference Power. Change those, not powerScale, when the field geometry changes.
  • Border races. The resetRequested = false + launchActive = false sequence has to come before the first checkBorder() call, or the bot will read the corner as a border and reset before the match starts.
