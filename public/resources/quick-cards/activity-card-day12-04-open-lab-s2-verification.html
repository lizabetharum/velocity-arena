Day 12 · Open Lab / Mini-Consolidation · 35 min
Follows Commissioner's Meeting
MATH: Constraint satisfaction in systems of inequalities — verify all constraints simultaneously
Before You Start
  • Write constraints as inequalities (e.g., Power ≥ 4)
  • Test allocation against all constraints simultaneously
  • Identify constraint conflicts before class
  • Fill Team Monitoring Chart with team names and constraint labels
  • Post Three-Step Reference on board
  • *Sequential checking is the most common error. Fix: verify all constraints simultaneously after every adjustment.*
Students Produce
  • Verified allocation sheet with sum = 20 and all constraints satisfied
  • MakeCode program with Season 2 stats loaded and saved
  • One test-drive observation in data log
  • Exit ticket: constraint as inequality + system verification
Reference
THREE-STEP REFERENCE
Step 1: Verify sum = 20, all rules satisfied, no blanks
Step 2: Program MakeCode with verified stats, save, load to bot
Step 3: Test drive, data log entry
TEAM MONITORING CHART: Track sum, each rule, programmed status, test completion
Timing
0:00LaunchPoint to wall rules. Ask teams to count constraints. Emphasize all at once, not sequentially. Say exact opening line.
0:01Partner checkListen for 'sum = 20 AND all rules satisfied.' If only 'sum = 20,' team will skip constraint verification.
0:01Step 1: Verify math (10–15 min)Circulate with chart. Ask 'Read me your totals.' Watch for sequential checking and conflicts.
0:15Step 2: Program MakeCode (8–12 min)Ask 'Is every number in MakeCode?' Confirm saved and loaded. Distribute: one enters, one reads, one verifies against wall.
0:25Step 3: Test drive (6–8 min)Ask 'What should be different from Season 1?' After run: 'Write one sentence — observation vs. prediction.'
0:32Mini-Consolidation & Exit Ticket (3 min)Pick one team with interesting constraint adjustment. Name the practice: constraint satisfaction in systems. Distribute exit ticket.
Say This
Open
Verify allocation, program MakeCode, test drive. Three steps in order — on the board. No one leaves until all three are done.
Constraint Activation
Rules that passed are on the wall. How many constraints does your team satisfy simultaneously today? All at once, not one at a time.
Test Drive
What should be different from Season 1? Write one sentence: what did you observe vs. predict?
Consolidation
You translated rules to math, checked simultaneously, ran the bot under new constraints. That is constraint satisfaction.
Not This
Do not relitigate votes. Say 'Write it in ENDS journal for the prediction market. Now start Step 1.'
Watch For → Redirect
Sum ≠ 20Ask 'Which stat changed under new rules? Start there.' Have them write values in order and add aloud.
Constraint conflictAsk 'What would minimums under both rules sum to?' If ≥ 20, flag room: requires class resolution.
Sequential checkingAsk 'Does Rule 1 still hold?' Enforce simultaneous verification after each adjustment.
Programming before Step 1 completeAsk 'Allocation verified? Program verified numbers, not drafts.'
One student programming, teammates disengagedDistribute: one enters, one reads sheet, one verifies against wall.
Bot behavior unexpectedSay 'Write what you observed. That is your first Season 2 data point.' Do not troubleshoot.
Hard Stop Exit ticket is non-optional. At 0:32: 'Write both before you leave.' Collect all. No bots leave until data log entry is written.
